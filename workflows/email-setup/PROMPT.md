# Start an assisted project-mailbox setup

New reusable template, prepared 8 November 2026. Fill the fields and have the owner explicitly request the task before executing it.

```text
Help me create one new project email mailbox using the provider's official
registration flow.

Owner / authorised representative: [owner]
Project and purpose: [purpose]
Preferred provider: [Gmail / Outlook.com / ask me]
Display name: [approved name]
Preferred address names: [two or three options, not assumed available]

Use workflows/email-setup/README.md as the procedure and read the current
browser-tool instructions. Confirm missing identity or provider details before
submitting a form. Check which account is active and preserve unrelated sessions.
Use only the owner's approved information; do not invent personal details.

You may help with naming, official-page navigation, ordinary approved signup
fields and progress explanations. Hand control to me for password entry,
verification codes, personal/recovery details, challenges and acceptance of the
provider's terms. Follow the environment's approval rules. Do not ask me to send
passwords or codes into chat, and do not store them in the repository.

After I complete those steps, inspect the result and confirm the intended new
mailbox is accessible. Distinguish creating a new mailbox from registering a
Google/Microsoft account using an existing address. If the outcome is uncertain,
record needs_review and inspect the existing account before retrying.

Keep only non-secret progress in workflows/email-setup/private/setup-record.json.
Do not publish the address, send mail, buy a plan, create other service accounts,
authorise apps or start social publishing as part of this request.

Report the provider, completion state, whether mailbox access was verified,
and the next owner action, if any. Do not call the setup complete until the new
mailbox is accessible and I confirm ownership.
```
